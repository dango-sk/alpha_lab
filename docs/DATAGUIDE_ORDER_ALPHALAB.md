## 2. [필수] 재무 원본 항목

**주기: 분기(Quarterly) + 연간(Annual) 둘 다.** 분기가 없으면 TTM을 못 만든다
(`lib/factor_engine.py:321` 이 `TTM_1Q~4Q`를 요구).

**연결/별도**: 현재 DB는 `finacc_typ`으로 구분하고 있으므로 **연결 우선, 없으면 별도** 형태로
두 계정 기준을 모두 받거나, 최소한 어느 기준인지 식별 컬럼이 있어야 한다.

### 2.1 손익계산서

| 요청 항목 | 매핑되는 내부 컬럼 |
|---|---|
| 매출액 | `revenue` |
| 매출총이익 | `gross_profit` |
| 영업이익 | `operating_income` / `ebit` |
| EBITDA (또는 영업이익 + 감가상각비) | `ebitda` |
| 당기순이익(지배주주) | `net_income` |

### 2.2 재무상태표

| 요청 항목 | 매핑되는 내부 컬럼 |
|---|---|
| 자산총계 | `total_assets` |
| 자본총계(지배주주) | `total_equity` |
| 이자발생부채(총차입금) | `interest_debt` |
| 순차입금 | `net_debt` |

### 2.3 현금흐름

| 요청 항목 | 매핑되는 내부 컬럼 |
|---|---|
| 영업활동현금흐름 | `pcf` 계산용 |
| CAPEX(유형자산 취득) | `fcf` = 영업CF − CAPEX |
| (또는 FCF 직접 제공 시 그것으로 대체) | `fcf` |

### 2.4 주당·기타

| 요청 항목 | 매핑되는 내부 컬럼 |
|---|---|
| EPS | `eps` |
| BPS | `bps` |
| 주당배당금(DPS) 또는 배당수익률 | `div_yield` |
| 발행주식수(보통주, 기말) | 시총 검증·주당지표 재계산용 |

### 2.5 우리가 계산할 파생값 (발주 불필요)

```
pbr        = 시가총액 / total_equity
per        = 시가총액 / net_income          (또는 주가 / eps)
psr        = 시가총액 / revenue
roe        = net_income / total_equity
roic       = ebit·(1−t) / ic,  ic = total_equity + interest_debt − 현금성자산
ev         = 시가총액 + net_debt
ev_ebit    = ev / ebit
ev_ebitda  = ev / ebitda
oi_margin  = operating_income / revenue
debt_ratio = interest_debt / total_equity × 100      # step6_build_universe.py:200 과 동일식
gpa        = gross_profit / total_assets
```

> 위 계산에 **현금성자산**이 필요하다(`ic`). §2.2에 "현금및현금성자산"을 추가로 요청할 것.

## 3. [필수] 공시일 — 이게 빠지면 확장의 의미가 절반

현재 look-ahead 방지는 고정 래그 근사다:

```python
# scripts/step6_build_universe.py:57
if month >= 4: return year - 1     # 4월 이후면 전년도 재무
else:          return year - 2
```

즉 "모든 기업이 3월 말까지 전년 실적을 공시한다"는 가정이다. 2000년대 초반은 공시
관행·기한이 지금과 달라 이 가정이 더 위험하다. 따라서 각 재무 레코드마다:

- **결산기준일** (fiscal period end)
- **실제 공시일 / 공표일** (announcement date, 정정공시면 정정일도)

를 함께 요청한다. 이게 있으면 "리밸런싱일 시점에 이미 공표된 최신 재무"라는 **진짜 PIT** 조인이
가능해지고, 확장 기간의 성과가 look-ahead 때문인지 아닌지를 다투지 않아도 된다.

## 4. [가능하면] 컨센서스 히스토리

`lib/factor_engine.py:330` 이 읽는 `fnspace_forward`, 그리고 `fnspace_consensus_daily`에 해당.

| 요청 항목 | 내부 컬럼 |
|---|---|
| Fwd EPS / PER / BPS / ROE | `fwd_eps` `fwd_per` `fwd_bps` `fwd_roe` |
| Fwd 매출 / 영업이익 / EBIT / EBITDA / 순이익 | `fwd_revenue` `fwd_oi` `fwd_ebit` `fwd_ebitda` `fwd_ni` |
| 연도별 추정치(est_*) + 추정 시점 | `fnspace_consensus_daily` |

**요건**: "현재 시점에서 본 과거 추정치"가 아니라 **그 시점에 시장이 갖고 있던 추정치의
스냅샷(as-of)** 이어야 한다. 소급 갱신된 값이면 look-ahead라 쓸 수 없다.

- 제공 가능하면: 일별이 이상적, 최소 **월말 스냅샷**
- 제공 불가하면: 확장 기간(2000~2017)은 **컨센서스 팩터를 제외한 축소 팩터셋**으로 백테스트하고,
  2018년 이후 구간과는 팩터셋이 다르다는 점을 결과에 명시한다.

## 4-B. [필수] Integrity Gate (STEP 2) 판정용 항목

Score와 무관한 **Hard Gate**(하나라도 FAIL이면 즉시 제외)라서, 결측이 곧 오판이 된다.
아래는 **DataGuide에서 받을 것**과 **DART에서 별도로 받아야 할 것**이 섞여 있으므로 출처를 나눈다.

### 4-B-1. DataGuide 재무에 추가 요청 (분기 기준)

| Gate | 필요 항목 | 계산 |
|---|---|---|
| 2-2 단기 유동성 (`CR < 0.70x`) | **유동자산**, **유동부채** | `CR = 유동자산 / 유동부채` |
| 2-1 자본잠식 | **자본금**(납입자본), 자본총계(§2.2 기확보) | 부분잠식 = 자본총계 < 자본금, 완전잠식 = 자본총계 < 0 |
| 2-3 잠재 희석 | **희석주식수**(diluted shares), 기본주식수 | 아래 주석 참조 |

- Sensitivity Test(`0.5x / 0.7x / 1.0x`)를 하려면 CR 원값이 필요하다 → 비율이 아니라 **유동자산·유동부채 원항목**으로 받을 것
- **금융업 제외 적용**이므로 업종 구분이 필요한데, 이건 §1 `panel_m.ind_code`로 커버된다
- `자본금`은 §2.2에 없던 항목이다. 추가 필수

### 4-B-2. 잠재 희석(2-3) — 이게 가장 까다롭다

`PDR = 잠재 신주수 / 현재 발행주식수`, 기준이 **권면총액이 아니라 전환가능 주식수**다.
DataGuide가 다음 중 무엇을 주는지 확인해야 한다.

1. **CB/BW/전환우선주 미상환 잔액 + 전환가액 + 전환가능주식수** (as-of) — 이게 있으면 그대로 사용
2. 없으면 **희석주식수 − 기본주식수**로 근사. 단 희석주식수는 회계상 희석효과 판정(역희석 제외)이
   들어가 있어 PDR을 **과소평가**한다. 근사임을 명시하고 쓸 것
3. 둘 다 없으면 **DART**: 전환사채 발행결정, 신주인수권부사채 발행결정, 전환청구권 행사 공시를
   누적해 미상환 잔량을 재구성 → 공수 큼

→ **발주 시 1번이 되는지부터 물어볼 것.** 되면 DART 작업이 통째로 사라진다.

### 4-B-3. DART에서 받아야 하는 것 (DataGuide 범위 밖일 가능성 높음)

| Gate | 필요 데이터 | 출처 |
|---|---|---|
| 2-1 감사의견 비적정 | 감사보고서 **감사의견**(적정/한정/부적정/의견거절) + 의견일자 | DART 감사보고서. DataGuide가 감사의견 필드를 제공하면 그걸로 대체 |
| 2-1 계속기업 불확실성 | 감사보고서 **계속기업 존속능력 불확실성 강조사항** 유무 | DART. 텍스트 플래그 |
| 2-4 대규모 유상증자 | **확정된** 유상증자 신주 발행예정주식수 + 이사회결의일/공시일 | DART "유상증자 결정" 공시 |

- 2-4는 "이미 공시되어 발행이 확정된" 건만 대상 → **공시일 기준 as-of**가 필수. 사후 철회·정정 건은
  철회일 이후 제외되어야 하므로 **정정·철회 공시도 함께** 수집해야 한다
- 감사의견·계속기업은 연 1회 이벤트지만 **의견일자 기준 as-of**로 붙여야 한다.
  결산기준일로 붙이면 감사보고서 제출 전 정보를 미리 아는 셈이 되어 look-ahead다

### 4-B-4. PIT 요건 (Gate 전반)

Integrity Gate는 전부 "리밸런싱 시점에 시장이 알 수 있었는가"가 판정 기준이다. 따라서
§3의 공시일 요구가 여기에도 동일하게 적용되며, 특히 다음은 **날짜 없이는 사용 불가**다.

- 감사의견 / 계속기업 → 감사보고서 제출일
- 유상증자 확정 → 결정 공시일 (+ 정정·철회일)
- CB/BW 잔량 → 발행일 및 전환청구 행사일
